# 本地算法优化维度专家发散汇总

日期：2026-05-25

用途：明天和 Ning 讨论“本地算法优化维度”。主线是：云端给半小时 SOC guidance，本地从四类维度判断现场策略，最后把核心维度收敛成目标函数和硬约束。

## 1. 这次讨论的核心

云端给的 SOC guidance 不是本地必须照抄的命令，而是一个参考目标。本地还要看现场实时状态，比如车、电网、电池、报警、功率限制，然后输出最终策略。

这里说的“维度”，不是随便列关键词。它决定的是：

> 当车要快充、电网容量不够、电池 SOC 又要保留时，本地算法到底优先保谁、牺牲谁。

所以这次可以先不急着定最终算法，而是先把本地算法可能考虑的维度列全，再讨论第一版哪些维度最重要。

一句话版本：

```text
云端给半小时 SOC guidance；
本地结合车、电网、电池、安全状态；
在硬约束内输出充放电和充电桩功率策略；
第一版先以 EV 充电缺口最小化为主，SOC 跟随作为软约束。
```

## 2. 四个核心维度

本地算法可以从四类维度发散。每一类不是互相独立的，它们会互相冲突，所以后面才需要用目标函数和权重来收敛。

| 维度大类 | 这类维度回答什么问题 | 可以放进去的具体项 | 对本地策略的影响 |
|---|---|---|---|
| 1. 用户/运营体验维度 | 车主和站点运营希望什么结果 | 单车充电速度、充电缺口、完成时间、等待时间、会话成功率、多车公平性、枪位利用率 | 决定是否优先让车充得快、是否要保证每台车最低功率、是否要公平分配 |
| 2. 数学优化目标维度 | 目标函数里最小化或最大化什么 | 最小化 EV 充电缺口、最小化 SOC 偏离、最小化电网越限、最小化电池使用、最小化功率波动、最大化 EV delivered energy | 决定最后公式怎么写，以及不同目标之间怎么加权 |
| 3. 硬约束/风险维度 | 哪些东西绝对不能突破 | SOC 上下限、BMS 告警、PCS 功率上限、电网进口/反送限制、单枪功率上限、温度、通信过期、不能同时充放电 | 决定哪些策略直接不可行，不参与优化讨论 |
| 4. 云端-本地接口维度 | 云端给什么，本地回什么，怎么验证 | SOC guidance、有效期、允许偏差、置信度、电网限制、BESS 功率限制、本地动作、SOC 偏差、EV 缺口、偏离原因 | 决定本地怎么理解云端参考，以及怎么把结果回传给云端复盘 |

这四类维度的关系可以理解成：

```text
用户/运营体验：我们想要什么效果
数学优化目标：把想要的效果写进公式
硬约束/风险：哪些东西绝对不能违反
云端-本地接口：云端给什么，本地怎么执行和回传
```

## 2.1 用同一个输入解释维度如何影响策略

例如某个时刻：

```text
云端 SOC_ref = 70%
车请求功率 = 150 kW
电网最大可用功率 = 100 kW
电池最大可放电功率 = 50 kW
```

这个输入本身不会自动决定唯一策略。不同维度优先级会导致不同输出：

| 优先维度 | 可能输出的策略 | 含义 |
|---|---|---|
| 单车充电速度优先 | 电网 100 kW + 电池 50 kW，车拿到 150 kW | 用户体验最好，但 SOC 会下降 |
| SOC 跟随优先 | 如果当前 SOC 已低于 70% 或接近下限，电池少补或不补 | 保云端 SOC 参考，牺牲部分充电速度 |
| 电池寿命优先 | 电池不一定补满 50 kW，可能只补 20-30 kW | 避免高功率放电和频繁循环 |
| 多车公平性优先 | 如果多车同时来，总功率按规则分配 | 不让一台车吃满，另一台车长期不足 |
| 硬约束优先 | BMS 告警、SOC 过低、电网超限时，直接限制策略 | 安全限制高于所有优化目标 |

所以本地算法真正要解决的是：

> 在硬约束内，根据我们选择的维度权重，输出当前最合理的本地策略。

## 2.2 收敛成通用目标函数

第一版可以把本地策略写成一个“最小化总惩罚”的问题：

```text
min J =
  w_ev   * EV_充电缺口
+ w_soc  * SOC_偏离云端参考
+ w_grid * 电网越限惩罚
+ w_bess * 电池使用/寿命惩罚
+ w_ramp * 功率波动惩罚
+ w_fair * 多车公平性惩罚
```

其中：

```text
EV_充电缺口        = max(0, P_EV_request - P_EV_actual)
SOC_偏离云端参考   = abs(SOC_actual - SOC_ref)
电网越限惩罚       = max(0, P_grid_import - P_grid_limit)
电池使用/寿命惩罚  = abs(P_bess) 或高功率放电惩罚
功率波动惩罚       = abs(P_current - P_previous)
多车公平性惩罚     = 多车实际分配功率差异
```

硬约束单独列出来，不靠权重解决：

```text
SOC_min <= SOC_actual <= SOC_max
P_grid_import <= P_grid_limit
P_bess_discharge <= P_bess_discharge_max
P_bess_charge <= P_bess_charge_max
P_EV_i <= P_EV_i_max
BMS_alarm = false
不能同时充电和放电
云端 guidance 过期时进入 fallback
```

第一版建议：

```text
硬约束永远最高优先级；
w_ev 权重最大，先减少 EV 充电缺口；
w_soc 是软约束，尽量跟随云端 SOC；
w_bess、w_ramp、w_fair 先作为次级维度。
```

## 3. 用户与运营维度

| 维度 | 说明 | 可量化指标 | 冲突 |
|---|---|---|---|
| 单车即时充电速度 | 用户最直接感知“现在充得快不快” | 当前 kW、平均 kW、前 10 分钟补能 kWh | 和 SOC 保留、电池寿命、公平性冲突 |
| 单车完成时间 | 用户从插枪到离场多久 | session duration、到目标 SOC 的 ETA | 和全站吞吐、公平降额冲突 |
| 充电缺口 | 车想要的功率和实际拿到功率之间的差 | `P_request - P_actual` | 和电网容量、SOC 保留冲突 |
| 会话成功率 | 插枪后能不能顺利开始并完成 | 启动成功率、中断率、重插率 | 和复杂调度/频繁降额冲突 |
| 最低服务保障 | 不让某些车几乎拿不到功率 | 每车最低 kW、低功率持续时间 | 和总功率不足冲突 |
| 等待时间 | 排队多久 | 平均等待、P90/P95 等待、最长等待 | 和单车高功率冲突 |
| 排队可预测性 | 用户能不能知道大概要等多久 | ETA 误差、队列跳变次数 | 和实时动态调度冲突 |
| 全站吞吐 | 单位时间服务多少车/多少电 | 车/小时、kWh/小时、枪位利用率 | 和单车速度、公平性冲突 |
| 公平性 | 多车同时来时不能长期偏向一台 | 各车平均功率差、FIFO 违背次数 | 和低 SOC 急需车、最大吞吐冲突 |
| 高 SOC 占位抑制 | 接近满电的车继续占枪效率低 | SOC>80% 占用时长、尾段 kWh/min | 和单个用户满意度冲突 |
| 降额感知 | 用户能不能接受功率下降 | 降额次数、降额幅度、持续时间 | 和电网限制、SOC 保护冲突 |
| 功率稳定性 | 不要让充电功率频繁上下跳 | kW 波动率、调功次数 | 和实时最优调度冲突 |
| 离场率/放弃率 | 用户看到排队太久直接走 | abandon rate、排队后离场率 | 和等待预测有关 |
| 枪位利用率 | 枪有没有被有效使用 | 插枪利用率、有效充电利用率 | 和故障、车辆兼容性有关 |
| 车型接受能力识别 | 有些车本身吃不下高功率 | 请求功率 vs 实际吸收功率 | 否则会误判成站点降额 |

## 4. 数学优化目标维度

| 目标维度 | 典型表达 | 解决的冲突 |
|---|---|---|
| 最大化 EV delivered energy | 多给车充电 | 用户服务 vs 站点资源限制 |
| 最小化 EV unmet demand | 尽量减少充电缺口 | 车想要的功率 vs 实际可供功率 |
| 最小化 SOC guidance 偏差 | `abs(SOC_actual - SOC_ref)` | 云端策略 vs 本地实时需求 |
| 最小化 SOC reserve violation | SOC 不低于保留线 | 当前车速 vs 后续服务能力 |
| 最小化 grid limit violation | 不超过电网进口上限 | 充电高峰 vs 并网容量 |
| 最小化 BESS throughput | 少做无意义充放 | 当前服务 vs 电池寿命 |
| 最小化高 C-rate 惩罚 | 避免高倍率冲击电池 | 快速补能 vs 设备压力 |
| 最小化 power ramp | 功率不要剧烈变化 | 快速响应 vs 稳定控制 |
| 最小化 charger power change | 充电枪功率不要频繁跳 | 最优调度 vs 用户体感 |
| 最小化 mode switching | 避免充/放/待机频繁切换 | 精细最优 vs 控制稳定 |
| 最小化 PV curtailment | 有光伏时少弃光 | 光伏消纳 vs SOC/EV 容量 |
| 最小化 peak import | 降低电网峰值 | 需量成本 vs 用户速度 |

一个通用目标函数可以理解成：

```text
总目标 =
  EV 充电缺口
+ 电网越限惩罚
+ SOC 偏离云端 guidance 的惩罚
+ SOC 低于保留线的惩罚
+ 电池使用/寿命惩罚
+ 功率波动惩罚
```

不是说第一版都要做，而是这些都是可以进入目标函数的维度。

## 5. 硬约束与风险维度

| 维度 | 类型 | 简单表达 | 第一版 |
|---|---|---|---|
| SOC 最低保底 | 硬约束 | `SOC >= SOC_min` | 必须 |
| SOC 最高上限 | 硬约束 | `SOC <= SOC_max` | 必须 |
| 云端 SOC 目标区间 | 软约束 | `SOC_target_low <= SOC <= SOC_target_high` | 必须 |
| 低 SOC 禁止大功率放电 | 硬约束 | `SOC低 -> P_dis_max降额` | 必须 |
| BESS 最大放电功率 | 硬约束 | `P_bess_dis <= P_dis_max` | 必须 |
| BESS 最大充电功率 | 硬约束 | `P_bess_ch <= P_ch_max` | 必须 |
| PCS 额定功率 | 硬约束 | `abs(P_pcs) <= P_pcs_rated` | 必须 |
| 充放电互斥 | 硬约束 | 不能同时充放 | 必须 |
| 功率爬坡率 | 硬/软约束 | `abs(P_t - P_t-1) <= ramp` | 必须 |
| 电网进口上限 | 硬约束 | `P_grid_import <= grid_limit` | 必须 |
| 反送电限制 | 硬约束 | `P_grid_export <= export_limit` | 视场景 |
| 站内总功率平衡 | 硬约束 | 输入功率 = 输出功率 + 损耗 | 必须 |
| 单枪/充电桩功率上限 | 硬约束 | `P_ev_i <= P_ev_i_max` | 必须 |
| EV 实际可接受功率 | 约束 | 车辆吃不下就不能硬给 | 必须 |
| BMS 严重告警 | 硬约束 | 告警时禁充/禁放/停机 | 必须 |
| 温度上下限 | 硬约束 | 电芯/PCS 温度越界降额或停 | 必须 |
| 绝缘/消防/急停 | 硬约束 | 触发则退出控制 | 必须 |
| 电表/BMS/PCS 通信中断 | 硬约束/降级 | 数据不可用就不能冒险 | 必须 |
| 数据时间戳过期 | 硬约束/风险 | 旧数据不能拿来控制 | 必须 |
| 控制死区 | 稳定性约束 | 接近阈值不反复跳 | 必须 |
| 最小保持时间 | 稳定性约束 | 不频繁切换模式 | 必须 |
| 故障后软启动 | 恢复约束 | 恢复时功率慢慢升 | 必须 |

## 8. 决策变量和状态变量

状态变量：

- 当前 SOC；
- 当前 BMS/PCS 可充可放功率；
- 当前电网可用功率；
- 当前 EV 请求功率；
- 当前连接车辆数；
- 当前站内负荷；
- 云端 SOC guidance；
- guidance 是否过期；
- 上一时刻功率指令；
- 故障/告警状态。

决策变量：

- 每台车实际分配功率；
- 储能柜放电功率；
- 储能柜充电功率；
- 是否限制充电桩总功率；
- 是否进入保守/降级模式；
- 是否偏离云端 SOC guidance；
- 偏离原因。

## 9. 第一版建议聚焦

第一版不要追求全局最优，也不要一开始做复杂电价套利。

建议第一版聚焦：

| 优先级 | 维度 | 用法 |
|---|---|---|
| P0 | 安全和硬约束 | BMS、SOC、电网容量、功率上限不可违反 |
| P0 | EV 充电缺口 | 尽量让实际给车功率接近请求功率 |
| P0 | 最低服务保障 | 不让某台车长期几乎没有功率 |
| P0 | SOC guidance 软跟踪 | 不盲目追，但偏离要有原因 |
| P0 | 云端/本地接口闭环 | 云给目标，本地回传偏差和原因 |
| P1 | 功率稳定性 | 不要频繁大幅上下跳 |
| P1 | 公平性/FIFO | 多车时默认简单公平规则 |
| P1 | BESS throughput | 避免无意义耗电池 |
| P1 | 储能支援效果 | 统计 BESS 是否真的减少缺口 |
| P2 | 电价收益 | 后续再优化 |
| P2 | 复杂寿命模型 | 后续再加入 |
| P2 | 预约/车队模型 | 后续再加入 |

## 10. 第一版可以讲的数学框架

先不要讲复杂公式，只讲这个：

```text
目标：尽量减少 EV 充电缺口

同时：
1. 不能超过电网容量；
2. 不能突破电池安全边界；
3. 不能让 SOC 严重偏离云端 guidance；
4. 不能让功率频繁大跳；
5. 如果做不到，要回传原因。
```

概念公式：

```text
总成本 =
  EV 充电缺口
+ 电网越限惩罚
+ SOC 偏离惩罚
+ 电池使用惩罚
+ 功率波动惩罚
```

第一版推荐口径：

> 本地算法先不做复杂套利，而是做“服务底线 + 缺口最小化 + SOC 软约束”。也就是说，车来了以后，本地尽量用电网和储能补足充电需求；但如果电池 SOC 太低、BMS 告警、电网容量不够，就必须牺牲部分充电速度，并把偏离原因回传给云端。
